# RAG Data Ingestion Pipeline

A practical Retrieval-Augmented Generation (RAG) project for loading PDF documents, splitting them into searchable chunks, generating sentence embeddings, storing vectors in ChromaDB, retrieving relevant context, and generating answers with a Groq-hosted language model.

The project is currently organized as interactive Jupyter notebooks so each stage of the pipeline can be inspected and tested independently.

## What this project does

This repository demonstrates an end-to-end document question-answering workflow:

1. Finds PDF files in the data directory.
2. Extracts text from each PDF page.
3. Splits extracted text into overlapping chunks.
4. Generates embeddings with `sentence-transformers`.
5. Persists embeddings and metadata in ChromaDB.
6. Retrieves the most relevant chunks for a user query.
7. Sends the retrieved context to a Groq LLM to produce an answer.

Empty PDF pages are ignored so scanned or textless pages do not create invalid empty embeddings.

## Pipeline overview

```text
PDF files
   │
   ▼
PDF loader (PyPDFLoader / PyMuPDFLoader)
   │
   ▼
Text splitter
   │
   ▼
SentenceTransformer embeddings
   │
   ▼
ChromaDB vector store
   │
   ▼
Similarity retrieval
   │
   ▼
Groq LLM response
```

## Prerequisites

- Python **3.13** (the required version is recorded in [`.python-version`](.python-version)).
- [UV](https://docs.astral.sh/uv/) or another Python environment manager.
- VS Code with the [Jupyter extension](https://marketplace.visualstudio.com/items?itemName=ms-toolsai.jupyter), or a local Jupyter installation.
- A Groq API key for LLM response generation.

## Installation

From the repository root:

```powershell
uv sync
```

If you are using a regular virtual environment instead of UV:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Launch Jupyter with:

```powershell
uv run jupyter lab
```

Or open the repository in VS Code and select the project virtual environment as the notebook kernel.

## Configuration

Create or update [`.env`](.env) in the repository root:

```env
GROQ_API_KEY=your_groq_api_key
```

Never commit a real API key. The repository already ignores `.env` through [`.gitignore`](.gitignore).

The notebooks use the Groq model configured in the notebook. If Groq retires a model, update the `model_name` value to one listed in the [Groq model documentation](https://console.groq.com/docs/models).

## Running the notebooks

For the full workflow:

1. Open [`AdvancedRAGwithLLM.ipynb`](notebook/AdvancedRAGwithLLM.ipynb).
2. Select the project Python 3.13 kernel.
3. Run the cells in order, beginning with imports and PDF loading.
4. Confirm that PDFs produce non-empty text chunks.
5. Run the embedding and vector-store cells.
6. Run a retrieval query.
7. Run the simple or advanced RAG cells after setting `GROQ_API_KEY`.

The recommended execution order is:

```text
imports
→ PDF loading
→ text splitting
→ embedding manager
→ vector store
→ document ingestion
→ retriever
→ Groq setup
→ RAG query
```

## Adding documents

Place new PDF files in [`data/pdf/`](data/pdf/), then rerun the loading, splitting, embedding, and ingestion cells.

For scanned PDFs, text extraction may return empty pages. OCR the PDF first, or use an OCR-capable loader, before generating embeddings.

## Troubleshooting

### No chunks are generated

Check that the PDF contains selectable text. A PDF can have pages but still contain no extractable text if it is image-only.

### Chroma rejects empty embeddings

Do not call the vector-store insertion cell when `chunks` or `texts` is empty. The notebook includes a guard that skips insertion and explains how to correct the source PDF.

### Groq reports a decommissioned model

Update `model_name` in the notebook to a currently supported model listed in the [Groq models documentation](https://console.groq.com/docs/models), then rerun the LLM setup cell before running a RAG query.

### Retrieval works but LLM calls fail

Check that:

- `GROQ_API_KEY` exists in `.env`.
- The notebook kernel is using the same environment where dependencies are installed.
- The selected Groq model is available for your account.
